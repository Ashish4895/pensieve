# Deploy EC2 Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a separate GitHub Actions workflow that SSHs to EC2 and pulls/up Compose after a successful Publish GHCR run on `main`.

**Architecture:** `deploy-ec2.yml` listens to `workflow_run` of `Publish GHCR` plus `workflow_dispatch`. Remote commands update `~/pensieve` and run `docker-compose.prod.yml` pull/up. Secrets hold host/user/key.

**Tech Stack:** GitHub Actions, SSH (`appleboy/ssh-action`), Docker Compose on EC2.

## Global Constraints

- Approach A: separate workflow; do not add deploy job inside `publish-ghcr.yml`.
- Deploy only when publish succeeded on `main` (or manual dispatch).
- Secrets: `EC2_HOST`, `EC2_USER`, `EC2_SSH_KEY`; optional `EC2_PORT`, `EC2_APP_DIR`.
- v1 uses `latest` after pull (no sha pin yet).
- Spec: `docs/superpowers/specs/2026-09-10-deploy-ec2-design.md`.
- Do not commit private keys or real host credentials.

- [ ] **Step 2: Create workflow with this exact content**

```yaml
name: Deploy EC2

on:
  workflow_run:
    workflows: ["Publish GHCR"]
    types: [completed]
  workflow_dispatch:

jobs:
  deploy:
    name: deploy
    runs-on: ubuntu-latest
    if: >
      github.event_name == 'workflow_dispatch' ||
      (github.event.workflow_run.conclusion == 'success' &&
       github.event.workflow_run.head_branch == 'main')
    steps:
      - name: Deploy over SSH
        uses: appleboy/ssh-action@v1.2.0
        with:
          host: ${{ secrets.EC2_HOST }}
          username: ${{ secrets.EC2_USER }}
          key: ${{ secrets.EC2_SSH_KEY }}
          port: ${{ secrets.EC2_PORT || 22 }}
          script_stop: true
          script: |
            set -euo pipefail
            APP_DIR="${{ secrets.EC2_APP_DIR }}"
            if [ -z "$APP_DIR" ]; then
              APP_DIR="$HOME/pensieve"
            fi
            cd "$APP_DIR"
            git fetch origin main
            git checkout main
            git pull --ff-only origin main
            docker compose -f docker-compose.prod.yml pull
            docker compose -f docker-compose.prod.yml up -d
            docker compose -f docker-compose.prod.yml ps
```

Note: `secrets.EC2_PORT || 22` may not work in all Actions expressions. Prefer:

```yaml
port: ${{ secrets.EC2_PORT != '' && secrets.EC2_PORT || 22 }}
```

Or hardcode `port: 22` and document optional override by editing the workflow if needed. **Use `port: 22`** for YAGNI unless `EC2_PORT` is set via env in the action (appleboy supports `port` as string `"22"`).

Final port line for v1:

```yaml
port: 22
```

Document that non-22 requires changing the workflow or adding `EC2_PORT` later.

For `EC2_APP_DIR`, empty secret is awkward—use only `$HOME/pensieve` in the script for v1 (YAGNI). Spec allows optional secret; implement default path only:

```yaml
script: |
  set -euo pipefail
  cd "$HOME/pensieve"
  git fetch origin main
  git checkout main
  git pull --ff-only origin main
  docker compose -f docker-compose.prod.yml pull
  docker compose -f docker-compose.prod.yml up -d
  docker compose -f docker-compose.prod.yml ps
```
